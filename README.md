# הסרת משתמש (User Remove Tool)

<div dir="rtl">

כלי שורת פקודה (עם חלון חיפוש קטן) לצוותי Help Desk ו-System להסרת משתמש מ-Active Directory ולפתיחת קריאה ב-CA Service Desk.

## דרישות

- Windows 10/11 או Windows Server 2016 ומעלה, 64 ביט. אין צורך בהתקנת ‎.NET.
- מחשב בדומיין, ומשתמש מחובר עם הרשאות להסרת חברים מקבוצות, להעברת משתמשים ל-OU היעד ולהשבתת חשבונות.
- Microsoft Edge וגישה לשרת CA Service Desk.

## הפעלה

התוכנה מגיעה מוכנה: התיקייה `publish` כבר כוללת קובץ הפעלה בנוי (`UserRemoveTool.exe`) וקובצי ההגדרות. אין צורך לבנות או לפרסם דבר.
לוחצים פעמיים על `Launch.bat` (בשורש הפרויקט או בתוך `publish`). הוא רק מפעיל את הקובץ הקיים, בחלון טרמינל, כשתיקיית העבודה היא תיקיית קובץ ההפעלה, כך ש-`appsettings.json` נמצא כראוי.
להפצה מעתיקים את כל תיקיית `publish` לתחנה.

## מהלך העבודה

התוכנה רצה בחלון טרמינל (קונסולה). רק חיפוש המשתמש נפתח בחלון קטן. אישורים והמשך התהליך נעשים בטרמינל: מקלידים `כן` או `y` לאישור, וכל תשובה אחרת (או Enter) היא סירוב. התקדמות השלבים מוצגת בשורה `[###---] שלב 3 מתוך 6`.

1. **חיפוש (חלון):** החיפוש מתבצע תוך כדי הקלדה (מהתו השני, בהשהיה קצרה), ב**כל מדריך הכתובות** (Global Catalog של כל היער, ולא רק הדומיין), כולל חשבונות מושבתים ואנשי קשר. כל מילה מחפשת בכל מקום בתוך: שם מלא, cn, name, שם פרטי, שם משפחה, שם משתמש, UPN, מייל, proxyAddresses, תיאור ו-`extensionAttribute1` (תעודת זהות). משפט כמו `משה כהן` מחייב שכל המילים יימצאו. בכל שורה מוצגים הסוג והדומיין. אם ה-Global Catalog לא זמין, החיפוש עובר אוטומטית לחיפוש בכל דומיין בנפרד, וההודעה מציינת זאת. אנשי קשר מוצגים אך אי אפשר לבחור בהם. מנווטים בין התוצאות בחצים ↑↓, ובוחרים ב-Enter או בלחיצה כפולה, או לוחצים **המשך** (כחול). **ביטול** (אדום) סוגר ללא שינוי.
2. **קריאת נתונים:** מוצגים השם, המייל, תיקיית הבית, ה-OU, ו-NationalId (מתוך `extensionAttribute1`). הנתונים נשמרים בזיכרון ובקובץ JSON זמני בתיקייה `%TEMP%\UserRemoveTool`, שנמחק בסיום.
   בדיקת NationalId נעשית כמספר זהות ישראלי (עד 9 ספרות עם ספרת ביקורת). אם הערך ריק או אינו תקין, התוכנה מתריעה ושואלת אם להמשיך. ההחלטה נרשמת ביומן הביקורת. זו הנחה שלי לגבי כלל הבדיקה, ואם הכלל שונה יש לעדכן את `NationalIdValidator.cs`.
3. **הסרת קבוצות:** מוצגת רשימת הקבוצות ומתבקש אישור. לכל קבוצה מוצג סטטוס (הוסרה או נכשלה, ובצבע). `Domain Users` אינה מוסרת לעולם. אם קבוצה אחת נכשלה, אפשר לנסות שוב, אך אי אפשר להמשיך עד שכולן הוסרו.
4. **העברה והשבתה:** מוצגת ההודעה "פעולה זו תעביר את המשתמש ל-Disabled Users ותבצע Disable לחשבון." ומתבקש אישור. ההשבתה מתבצעת רק אחרי שההעברה הצליחה.
5. **פתיחת CA:** חלון Edge נפתח אוטומטית. אם מופיע מסך כניסה, מתחברים בו והתהליך ימשיך לבד.
6. **מילוי קריאה:** התוכנה ממלאת את השדות, בודקת אותם ומפסיקה. היא **אינה שומרת ואינה שולחת**. יש לבדוק את הקריאה ב-Edge וללחוץ ידנית על **שלח קריאה**.

אם שדה לא מולא, הוא מסומן באדום והערך שלו מודפס בטרמינל להעתקה ידנית. `Ctrl+C` בזמן מילוי הקריאה מבטל רק את המילוי.

**תצוגת עברית בטרמינל:** חלונות הקונסולה של Windows (cmd, PowerShell ו-Windows Terminal) מציירים טקסט משמאל לימין בלבד ואינם מסדרים עברית מימין לשמאל, ולכן עברית רגילה מופיעה הפוכה. התוכנה מסדרת את העברית בעצמה: מילים בעברית מוצגות בסדר נכון, ושמות, נתיבים ו-OU באנגלית נשארים כפי שהם (למשל `extensionAttribute1` ו-`\\fs01\home$\danac`). השורות מיושרות לימין ושורות ארוכות נשברות. `Launch.bat` מגדיר UTF-8 (`chcp 65001`). אם מופיעים סימני שאלה, יש לבחור גופן עם עברית (למשל Consolas או Cascadia). אם הטרמינל שלכם מסדר עברית בעצמו והטקסט מופיע הפוך, יש להגדיר `Terminal:VisualHebrew` ל-`false`. קובצי היומן נשמרים בסדר רגיל ב-UTF-8, ללא היפוך.
### אם התהליך נקטע

בוחרים שוב את אותו משתמש. שלבים שכבר בוצעו מזוהים ואינם מבוצעים פעמיים.

## הגדרות

הקובץ `appsettings.json` נמצא ליד קובץ ההפעלה. שינוי נכנס לתוקף בהפעלה הבאה.

| הגדרה | משמעות |
|---|---|
| `ActiveDirectory:DomainController` | שם הדומיין או שרת ה-DC |
| `ActiveDirectory:TargetOu` | ה-OU שאליו מועבר המשתמש |
| `ActiveDirectory:SearchEntireDirectory` | ‏`true` (ברירת מחדל): חיפוש ב-Global Catalog של כל היער. ‏`false`: רק הדומיין שב-`DomainController` |
| `ActiveDirectory:GlobalCatalogServer` | שם שרת Global Catalog (אופציונלי; ריק = נמצא אוטומטית) |
| `ActiveDirectory:IncludeContacts` | הצגת אנשי קשר (Contact) בתוצאות |
| `ActiveDirectory:MaxResults` | מספר המשתמשים המרבי שמוצג בחיפוש (ברירת מחדל 1000, עד 10000) |
| `ServiceDesk:Url` | כתובת CA Service Desk |
| `ServiceDesk:NewTicketUrl` | כתובת חלון הקריאה החדשה |
| `ServiceDesk:AssigneeGroup` | צוות מטפל |
| `ServiceDesk:Assignee` | גורם מטפל |
| `ServiceDesk:Source`, `Status` | מקור הקריאה וסטטוס |
| `ServiceDesk:CategoryPath`, `CategorySeparator` | נתיב הקטגוריה והתו המפריד ב-CA |
| `ServiceDesk:SingleLineSeparator` | המפריד כאשר "תיאור מקוצר" הוא שדה של שורה אחת |
| `ServiceDesk:OpenStrategies` | סדר הניסיונות לפתיחת קריאה: `PopupUrl`, `Menu`, `CreateNewUrl` |
| `ServiceDesk:MenuTexts` | הטקסט של פריט התפריט "קריאה חדשה" |
| `ServiceDesk:Fields` | מיקום כל שדה בטופס: `Selectors` (CSS) ואחריהם `Labels` (כותרת השדה) |
| `ServiceDesk:LoginTimeoutSeconds`, `FormTimeoutSeconds` | זמני המתנה |
| `Logging:Directory` | תיקיית היומנים |
| `Logging:AuditDirectory` | תיקייה נפרדת ליומן הביקורת, למשל שיתוף מרכזי |

יש להגן על תיקיית ההתקנה מפני כתיבה של משתמשים רגילים, כי שינוי בהגדרות משנה את יעד הפעולות.

## יומנים

ברירת המחדל: `%LOCALAPPDATA%\UserRemoveTool\Logs`

- `app-*.log`: יומן טכני ושגיאות.
- `audit-*.jsonl`: יומן ביקורת. כל שורה כוללת זמן, מבצע, מחשב, פעולה, תוצאה ומשתמש יעד. הקבוצות שהוסרו רשומות בו במלואן, כך שאפשר לשחזר אותן ידנית. אם אי אפשר לכתוב ליומן הביקורת, הפעולה נעצרת.

## בטיחות

- משתמש נבחר מתוך כל היער, אך כל הפעולות עליו (קריאת נתונים, קבוצות, העברה והשבתה) מתבצעות מול ה-Domain Controller של הדומיין שלו. ה-OU היעד נמצא בדומיין `moia.gov.il`, ולכן משתמש מדומיין אחר נדחה לפני כל שינוי, כי אי אפשר להעביר אובייקט בין דומיינים בהעברה רגילה.
- ההתחברות ל-AD היא בזהות המשתמש המחובר, בתעבורה חתומה ומוצפנת, מול DC אחד לכל אורך העבודה.
- אי אפשר להסיר את המשתמש שמפעיל את התוכנה או חשבון מערכת מובנה. על חשבון עם `adminCount=1` מוצגת אזהרה.
- ‏OU היעד נבדק לפני שמתחיל שינוי כלשהו.
- אם הקבוצה הראשית אינה `Domain Users`, היא מוחלפת ב-`Domain Users` ואז מוסרת. אם המשתמש אינו חבר ב-`Domain Users`, מוצגת שגיאה ונדרש טיפול ידני.
- המילוי האוטומטי משתמש בפרופיל Edge נפרד, בתיקייה `%LOCALAPPDATA%\UserRemoveTool\EdgeProfile`. כל עוד חלון זה פתוח, פתוח בו ערוץ שליטה מקומי שאינו נגיש מהרשת אך נגיש לתוכנות באותו מחשב. יש לסגור את החלון בסיום.

## פתרון תקלות

| תקלה | טיפול |
|---|---|
| לא ניתן להתחבר ל-Domain Controller | לבדוק חיבור לרשת הארגון ואת `DomainController` |
| אין הרשאה לבצע את הפעולה | להפעיל עם משתמש בעל ההרשאות המתאימות |
| כבר קיים אובייקט באותו שם ב-OU היעד | לשנות את שם האובייקט הקיים ב-ADUC ולנסות שוב |
| לא ניתן להתחבר ל-Edge | לבדוק את מדיניות `RemoteDebuggingAllowed` של Edge |
| טופס קריאה חדשה לא זוהה | לוודא ש-CA אינו מוגדר לפתיחה ב-IE Mode, ולבדוק את `OpenStrategies` ואת `MenuTexts` |
| שדה לא נמצא בטופס | לעדכן את `Fields` לפי שם השדה (F12 ב-Edge) |
| הערך אינו קיים ברשימה | לוודא שהטקסט זהה לערך ב-CA |

## בנייה

נדרש ‎.NET SDK 8 ומעלה וגישה ל-NuGet.

</div>

הבנייה נדרשת רק למפתחים, לאחר שינוי בקוד. ‏`Launch.bat` אינו בונה. הפקודה מעדכנת את התיקייה `publish`:

```bat
dotnet publish src\UserRemoveTool\UserRemoveTool.csproj -c Release -r win-x64 --self-contained true -p:PublishProfile=win-x64 -o publish
dotnet test
dotnet test --filter Category!=Edge
```
